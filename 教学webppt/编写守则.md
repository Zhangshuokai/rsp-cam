# 教学 webppt 规范与编写守则

适用于 `教学webppt/` 下全部主题 deck。三块硬约束：**组织**（怎么分与放）、**语言**（每页怎么说）、**顺序**（先讲什么后讲什么）。

制定依据（联网检索 + 领域通行结论）：

- 多媒体学习认知理论（Mayer）：多媒体、空间/时间邻近、一致性（去冗余）、信号（突出关键）、分段（一页一段）原则。
- 通用教学 PPT 设计规范：形式服从内容、统一母版/字体、一页一个主题、正文行距 ≥1.5、图片文字不改比例、知识点穿插不堆砌。
- 金字塔原理：结论先行、以上统下、归类分组、逻辑递进。

与 `web-slide-deck` 技能的「非协商项」配合使用，冲突时以技能里的技术约束为准。

---

## 一、组织

一个主题 = 一个 deck；主题名 = 目录名 = `index.html` 里的卡片标题 = 提交主题。

- `index.html` — 目录首页（固定导航入口）
- `编写守则.md` — 本文件
- `README.md` — 使用 / 构建说明
- `<主题>/`
  - `index.html` — 成品：单文件、离线可双击
  - `presentation/` — 源码（Vite + React + Tailwind）

- **单文件交付**：成品 CSS/JS 全内联，双击即播；源码与成品必须一致。
- **每 deck 固定骨架**：封面 → 概览（结论先行）→ 主体分组（2–5 组，超过 5 组考虑拆 deck）→ 收尾（小结 / 清单 / 下载）。
- **大纲（sidebar 的 group）线性、不嵌套**，组名 2–6 字，与页面 `nav` 同用中文短词；「目录」专指 `教学webppt/index.html`，deck 内分页侧栏一律叫「大纲」。
- 主题粒度：一次提交 / 一个交付主题一个 deck，不把无关主题塞进同一 deck。
- 图片放 `presentation/src/assets/`，由构建内联；`node_modules/`、`presentation/dist/` 不入库。
- **附件放 `<主题>/files/`**：随 deck 分发的可下载文件（PDF / zip 等）放成品同级的 `files/`，deck 里用相对链接 `./files/…` 引用；**大文件不内联**进单文件 HTML。

## 二、语言

面向学生讲课，不是写论文，也不是抄文档。

- **一页一个知识点**，标题写结论或判断（「建议 12V 版」「为什么选 ROS 2」），不写「关于……的介绍」。
- **正文 ≤ 6 行要点**，每行一句话；能图不表、能表不字；多余装饰、段子、无关配图一律删。
- **图表用真实矢量图**：流程 / 架构 / 结构一律**禁止 ASCII 字符画**（`─` `│` `┌` `└` `├` `▼` 等）与**线框图**。deck 里用内联 `<svg>`（成品离线单文件，不引 CDN / Mermaid 运行时）；Markdown 里用 ` ```mermaid ` 代码块（GitHub / GitLab 渲染为 SVG）；目录结构用嵌套列表。
- **详情默认折叠**：完整步骤、全量命令、备选方案放进折叠块（`<details>`，摘要写「展开：…（完整步骤）」），默认收起；正文只留要点，保证一页一个知识点。共用组件 `Steps` / `Pre` 放在各 deck 的 `components.jsx`（各 deck 保持完全一致）。
- **详细内容同步到 docs**：折叠块里的完整内容（参数表、全量命令、排障清单）要同步落在对应的 `docs/*.md`（Markdown + `mermaid`，GitHub 可直接渲染），deck 收尾页给出该 md 的入口；两处改动保持一致。
- **术语首现**写「中文（English）」，之后全文统一一种写法；同一概念不换词。
- 命令、代码、路径、寄存器名用等宽/`code` 样式；数字带单位（`1080p@30fps`、`1.3 ms`）。
- 中文标点用全角；中英文之间留一个空格；不堆 emoji、不中英混杂成句。
- 用第二人称/陈述短句，不照搬长段落；否定式提醒（「不要……」）单独成页或成条。

## 三、顺序

### 1) 全局主题顺序：工程与协作 → 环境与设备 → 感知 → 通信 → 执行

| 序 | 主题 | 定位 |
| - | --- | --- |
| 1 | 项目结构整理 | 总纲：目录、工程规范、协作约定 |
| 2 | 树莓派连接与部署 | 环境：直连、`tools/pi.py`、排障（后续实操前提） |
| 3 | 摄像头参数与选型 | 感知器件：UVC、参数、型号 |
| 4 | 摄像头远程显示 | 感知应用：采集/传输/显示解耦 |
| 5 | ROS 2 与 micro-ROS 选型 | 通信中间件：选型、部署、跨机验证 |
| 6 | ESP32-S3 电机驱动板 | 执行：硬件、开发、联网、ROS 2 对接 |
| 7 | ESP32-S3 接入 micro-ROS | 执行：S3 固件、Pi 端 Agent、通路验证 |
| 8 | ESP32 与 ROS 2 开发基础 | 课程：48 学时课程包与三层主线（设备 / 通信 / 系统） |
| 9 | ROS2综合集成进阶 | 进阶课：ROS 2 四节点集成实战（以图文详解版为教材） |
| 10 | 智能救援车辆设计 | 整车集成：1.5kg 限重下的整车方案 |
| 11 | 智能搬运车辆设计 | 整车集成：抓取 + 载运的事实标准方案 |
| 12 | 机器人入门复现路线 | 训练路线：Toolbox → Swift → MuJoCo → VLA 入门阶梯 |

新主题按此位置插入，并**同步** `index.html` 目录首页与 `README.md` 的「已有主题」。

### 2) 单 deck 页序（自上而下）

封面 → 结论先行 → 背景/现状 → 原理/选型 → 实施/部署 → 验证 → 日常使用 → 收尾。

- **收尾（小结 / 清单 / 下载）恒在最后一页之后**，不得被任何分组打断；发现越位就调整 `slides.jsx` 顺序。
- 由已知到未知、由简到繁；每页承接上一页，组间只前进不回跳。
- 分组名与页序一致：`概览 → 主体若干 → 收尾`，`收尾` 只能出现在末尾。
- **改顺序必须重建成品**：`cd <主题>/presentation && npm run build`，再把 `dist/index.html` 覆盖为上一级 `index.html`。

## 四、版式与校验

沿用 `web-slide-deck` 技能的非协商项：`min-h-full` 而非 `h-full`；keydown 只注册一次；切页重置 `main.scrollTop`；横滑翻页阈值 `|dx| > 55 && |dx| > |dy| * 1.3`；全屏要有 CSS 兜底。

交付前在 **1366×860** 和 **390×844** 逐页断言：

- `overflowX === 0`（无横向溢出）；
- 首行在 `scrollTop === 0` 时可见（不顶头）；
- 高页允许纵向滚动，只有顶部被裁才算 bug。

## 五、落地流程

1. 素材归档到 `教学webppt/<主题>/`（或对应 `docs/` 等目录）。
2. 先列大纲（`group` + `nav`），再写 `slides.jsx`。
3. `npm install` → `npm run build` → 用 `dist/index.html` 覆盖成品。
4. 按第四节逐页校验。
5. 更新 `教学webppt/index.html` 目录首页与 `README.md`「已有主题」。
6. 提交按 `docs(webppt): …` 风格写中文说明，不主动 push。

### 提交前自查

- [ ] 主题顺序符合第三节第 1 条，目录首页 / README 同步。
- [ ] 每 deck 有「封面 → 结论先行 → …… → 收尾」，收尾在最后。
- [ ] 每页一个知识点，标题是结论；正文 ≤ 6 行。
- [ ] 术语、单位、标点、中英文空格全文一致。
- [ ] 成品已重建，且与源码一致；桌面/手机校验通过。

推送与 `/init` 节奏见第六节。

## 六、仓库维护节奏（按规模执行 /init 与推送）

规模判据＝已积累**未推送 / 未刷新**的提交量；按量决定是否跑 `/init`、何时放行推送。

| 档 | 规模 | /init | 推送 |
| - | - | - | - |
| 小 | 1~2 笔提交（单册小修、文档补丁） | 不跑 | 攒批，随下一册一起推 |
| 中 | 累计 3~5 笔（通常 1~2 册重构） | 跑一次（增量刷新 `AGENTS.md`，不得删减既有章节） | 每册验收通过后由推送单放行 |
| 大 | 整批完成或累计 ≥8 笔 | 批末跑一次 | **按交付单元分批推送**（见第 4 条），不攒成一次巨型推送 |

### 1) /init 执行方式（本仓库口径）

无头执行：

```bash
kilo run --auto --dir <项目> --command init -m deepseek/deepseek-flash "在现有 AGENTS.md 基础上增量更新…"
```

执行后把 `AGENTS.md` 更新作为**单独一笔**提交：`docs: /init 刷新 AGENTS.md（…）`，并入当次推送。

### 2) 推送纪律

- 施工方（kcode）**不主动 push**；推送一律由监工验收后的「推送五步单」执行：fetch → `origin/main..HEAD` 对账 → ancestor 判定 → push → 读回；**禁任何强推**。
- 推送后由同步链上线（`auto_sync.sh`），核对 md5 三方一致（仓库＝站点＝公网）。

### 3) 积压红线

- 未推送累计 ≥5 笔，或距上次推送超过 24 小时 → 必须清算（或书面说明原因），不允许长期积压。

### 4) 大宗变更：分批提交与分批推送

- **分批门槛**：一批改动达到「≥5 笔提交」或「跨 ≥2 个交付单元（多册 deck / 多主题）」时，commit 与 push **一律按批次拆分**。每完成一个可交付单元（如每册 deck）即完成该单元的提交，验收放行后**立刻推送该批次**，不得积压成一次巨型推送。
- **推送节奏**：批次推送＝每批一张推送单，五步不变（fetch → `origin/main..HEAD` 对账 → ancestor 判定 → push → 读回）；上一批验收后即可推，**不必等全批完工**。
- **红线沿用**：第 3 条积压红线（≥5 笔或超 24h 必清算）不变；本条是「提前拆批」的加强，不是放宽。
- **反例**：一次性把十余册的改动攒到最后一把推，属于违规节奏。

## 七、图文并茂与记忆友好设计（职业本科适配）

面向**职业本科**学生（高考约 300–400 分段）授课：这一分段的认知特点是图形、流程、类比、案例记得住，成段的定义与推导记不住。所以 deck 的设计目标从「把知识讲全」改成「**用图记知识**」——让学生靠一张流程图 / 结构图 / 类比图完成记忆，而不是靠背文字。本节与第二、三节并列，写新页、改旧页一律遵守。

### 1) 读者画像与设计目标

- 读者：职业本科、高考约 300–400 分段；抽象符号阅读负担高，图像与结构化信息接收快。
- 记知识的方式：先看图建立「骨架」，再用一两句话把骨架说出来；不靠逐字背诵概念与基础理论。
- 设计目标：**用图记知识**，不是**用文字背知识**。看到图能复述流程，就算过关。

### 2) 每册底线：理解型图示

每个主体组（大纲的一个 `group`）**至少 1 张「理解型图示」**，四类任选其一以上：

| 类型 | 适合讲什么 | 例 |
| - | - | - |
| 流程图 | 有先后顺序的操作 / 数据流 | 采集 → 传输 → 显示 |
| 结构关系图 | 组成、包含、分层 | 三层链路：设备 / 通信 / 系统 |
| 对比图 | 两个及以上方案的取舍 | 直连 vs 走 Wi-Fi |
| 时序图 | 多角色按时间交互 | WSL ↔ Pi ↔ S3 的消息往返 |

- **关键操作流程必须可视图化**（一张图看懂顺序），不得只给文字步骤；完整命令 / 备选方案收进折叠块或 `docs/`。
- 图示按第二节硬约束落地：deck 用内联 `<svg>`，Markdown 用 ` ```mermaid `，目录结构用嵌套列表。

### 3) 表达优先级：图 ＞ 表 ＞ 文字

- 同一信息能画图就不画表，能列表就不写段：**图 ＞ 表 ＞ 文字段落**。
- **一页一图**（或一图一组的密度）：一张图配 ≤6 行要点；不堆图、不堆字。
- **禁止超过 6 行的纯文字「流程说明」页**：只写文字的步骤页属不合格页，必须改成流程图或补图后再讲。

### 4) 点式动画（流程类内容）

- 流程类内容配**点式动画**：逐步点亮 / 逐步展开，一步一个节点，替学生把流程「走一遍」，看懂顺序再记。
- **每册 ≤3 处**，点到为止；动画只服务顺序理解，不做装饰。
- **必须配静态兜底**：完整图是默认态，停帧 / 关动画 / 打印都看得全。
- 移动端 **390×844 不破版**：动画页同样按第四节断言（`overflowX === 0`、首行可见）。

### 5) 记忆锚

每章（收尾页所在的章节单元）**至少 1 个记忆锚**，四类任选其一以上，并在正文与图示里重复出现、互相强化：

- **口诀**：把步骤 / 参数压成朗朗上口的短句。
- **生活化类比**：拿学生熟悉的事物映射抽象概念（如「Agent 像翻译官」）。
- **场景化案例**：用一次真实调试 / 一次比赛任务串起全章知识点。
- **颜色编码**：同一含义固定同一颜色（报错红、成功绿），全册一致。

### 6) 禁止 ASCII 字符画

- **不得**用 `─` `│` `┌` `└` `├` `┐` `┘` `▼` 等框线符号拼接流程图 / 结构图 / 架构图，**代码块内的示意图同样禁止**。
- 一律用真实图形：deck 用内联 `<svg>`，Markdown 用 ` ```mermaid `；目录结构用嵌套列表。
- 交付前 `grep` 框线字符，**命中数必须为 0**；有命中即不合格，返工为图。

### 7) 教材同步

- 上述要求**同时适用于 `docs/` 文字版与 `<主题>/files/` 教材**：图示与 deck 同步、不删减，两处同源。
- 教材侧细则另见 `课程教材编写标准.md`（面向 Word / 活页式教材与配套文字版）。

### 8) 反例（各举一条）

- **反例 A｜纯文字流程说明页**：标题写「摄像头远程显示的流程」，正文用 8 行文字从「打开脚本」一路写到「看到画面」，整页没有一张图 —— 须改为一张流程图 + ≤6 行要点。
- **反例 B｜ASCII 框线架构图**：用 `┌────┐`／`│ 采集 │`／`└────┘` 之类符号在正文或代码块里拼出架构，或用 `──────` 画流程箭头 —— 一律删除，换成内联 `<svg>` / `mermaid`。
