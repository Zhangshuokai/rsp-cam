# 《ESP32 与 ROS 2 开发基础》教师手册

> 本手册汇集备课要点、课堂组织方法、设备管理、完整故障案例库与排障速查表。
> 案例全部来自本项目的真实开发过程，可直接作为课堂讨论素材（教师先讲现象，让学生猜原因）。

## 一、学情分析与教学对策

| 大一学生的典型特点 | 教学对策 |
|---|---|
| 对硬件好奇，动手意愿强 | 每次课先给"可见的现象"（灯、页面、日志），再讲原理 |
| 编程基础弱，怕报错 | 代码以可运行骨架为主，只留 1–3 个空让学生补；报错当教学素材 |
| 抽象概念（网络、ROS）理解慢 | 大量类比：IP=门牌号、端口=房间号、话题=微信群、节点=群成员 |
| 注意力持续时间短 | 45 分钟讲解中至少 2 次互动/演示；单次连续讲授 ≤15 分钟 |
| 水平差异大 | 每个实验设置"基础验收 + 拓展任务"，快的学生有挑战、慢的能完成 |
| 喜欢在手机上分享成果 | 鼓励录短视频/拍照作为实验记录；课堂展示优秀作品 |

## 二、教学策略

1. **现象先行**：每节课的第一次演示一定是"能看/能玩"的结果，原理放在现象之后。
2. **结对编程**：两人一组轮换"操作者/记录者"，每 20–30 分钟交换角色。
3. **故障驱动教学**：有意制造安全的小故障（拔网线、杀服务器进程、写错端口），让学生用分层法定位。
4. **黑板只画一张图**：每节课的核心知识收敛为一张链路图/状态图，课后拍照发班级群。
5. **软件工具使用纪律**：Thonny/串口助手/mpremote 不能同时占用同一个 COM 口（典型翻车点）。

## 三、教师课前准备清单

**环境（课程开始前一周完成）**

- [ ] 学生机镜像：Python 3.10+、`esptool`、`mpremote`、WSL2 + Ubuntu 24.04 + ROS 2 Jazzy；
- [ ] 教师机同样环境，并已验证 `colcon build` 可离线通过（构建产物可预生成到 `ros2_ws/install`）；
- [ ] 无线路由器/热点：**2.4G**，关闭 AP 隔离；记录 SSID/密码；
- [ ] 在教师机上把仓库完整克隆/拷贝到每台学生机（或 U 盘分发）；**第 6 周实验前**再生成每组的 `common/wifi_config.py`（含教师机 IP，实验一~五不要放置该文件，否则串口心跳消失）；
- [ ] 准备 1–2 块备用板、备用 USB 线。

**每节课前 5 分钟检查清单**

- [ ] 两块板插好、识别端口（CH343）；没被 Thonny/串口助手占用；
- [ ] 板子不在 REPL（必要时 `python -m mpremote connect COMx reset`）；
- [ ] 转发器与 `ros2 launch` 是否已启动（第 7 周起）；
- [ ] 路由器已开机、教师机 IP 未变；若变了，更新各组 `wifi_config.py` 的 `SERVER_IP` 并重新部署。

## 四、课堂组织建议（以 135 分钟为例）

| 时段 | 时长 | 活动 |
|---|---|---|
| 开场 | 10 min | 回顾上次验收点 + 展示本次目标的最终现象 |
| 讲解 | 30–40 min | 分 2–3 段，中间穿插提问与现场演示；不超过 15 分钟连续讲授 |
| 实操 | 60–70 min | 学生按实验指导操作，教师巡场；用"一分钟诊断"帮助卡住的学生 |
| 收尾 | 15–20 min | 抽 2–3 组当堂验收；总结一张图；布置作业；预告下节 |

**巡场技巧**：先看灯、再看日志、最后问代码——80% 的问题在日志里已经写明原因。

## 五、设备与分组管理

- 每组固定两块板，用贴纸写"组号-绿/蓝"；**板子的 COM 口每台电脑可能不同**，以设备管理器为准。
- 两个板子同时插同一台电脑时：先把两块板都复位，看串口输出 `[GREEN ...]` / `[BLUE ...]` 区分，**不要靠端口号猜板子**。
- 部署时严禁两个工具同时打开同一端口；教师机运行转发器/launch 的窗口不要关闭。
- 学生分组建议按"动手型 + 细心型"搭配；每组指定一名"设备管理员"负责保管板子和线材。

## 六、真实故障案例库（来自本项目开发日志）

> 用法：讲现象 → 学生讨论 2 分钟 → 给出原因与修复 → 提炼可迁移的排障方法。

### 案例 1：开发板"没有 Python"

- **现象**：按 Ctrl-C 没有 `>>>` REPL，串口一直打印 `example: log -> UART`。
- **原因**：出厂固件是 ESP-IDF 演示程序，板子根本没装 MicroPython。
- **修复**：用厂商提供的完整镜像（bootloader + 分区表 + 应用）烧写到 **0x0**。
- **教学点**：面对未知设备，先用可观测信息（串口日志、芯片探测）判断现状，再动手。

### 案例 2：`mpremote` 第一次连接总失败

- **现象**：`could not enter raw repl`，重试一次就好了。
- **原因**：首次进入 raw REPL 的时序问题，不是接线故障。
- **修复**：`tools/deploy.py` 内置一次重试（等 2 秒）。
- **教学点**："偶发失败先重试，稳定失败再排查"；把经验固化成脚本。

### 案例 3：上传成功但板子不运行

- **现象**：`cp` 上传后板子停在 REPL，`main.py` 不执行。
- **原因**：在同一次 mpremote 会话里链式执行 `cp ... + reset` 会残留 REPL 状态。
- **修复**：`reset` 用**独立连接**执行。
- **教学点**：工具的行为边界要用实验确认；部署脚本为什么要分两步。

### 案例 4：板子连得上电脑，连不上 WSL

- **现象**：板子能连 Windows 的监听端口，连 WSL 的端口报 `ECONNABORTED`。
- **原因**：WSL 镜像网络模式下，局域网 → WSL 的入站连接被 Hyper-V 防火墙拦截（规则需管理员权限）。
- **修复**：Windows 侧运行 `tcp_forwarder.py`，把 `LAN:6000` 转到 `WSL:127.0.0.1:6001`。
- **教学点**：分层定位（物理→网络→端口→应用）；工程中"绕开限制"与"修改系统"的取舍。

### 案例 5：服务器一重启，板子就掉线不回来

- **现象**：重启 `wifi_server` 后，板子不再出现在线列表。
- **原因**：旧 TCP 连接是半开状态，板子没有感知到对端关闭，也没有重连逻辑。
- **修复**：链路层在 `send`/`recv` 出错时丢弃 socket 并每 4 秒重连（实测 12 秒内恢复）。
- **教学点**：网络程序必须处理"连接失效"；心跳 + 重连是物联网设备的标配。

### 案例 6：页面每刷新一次就多一条样式

- **现象**：旧页面刷新后样式列表越来越长；板子本身并没有重复。
- **原因**：旧版页面把历次 `STYLE LIST` 回复累加解析；且浏览器缓存了旧页面。
- **修复**：解析只取最后一个 `STYLE-END` 前的连续块并按名字去重；服务端加 `Cache-Control: no-store`。
- **教学点**：客户端缓存是常见坑；协议解析要明确"一个响应的边界"。

### 案例 7：保存新样式后，原来的闪烁被"覆盖"了

- **现象**：用户反馈"加样式后原来的闪烁没了"。
- **原因**：板端与界面都把"保存"做成了"保存并立即应用"。板端 `default` 其实一直健在。
- **修复**：`STYLE SET` 只保存；切换必须 `STYLE USE`；界面按钮改为"保存样式"并加说明。
- **教学点**：需求要听准确（用户说的"覆盖"其实是"切换"）；把用户反馈转化为设计规则。

### 案例 8：一颗灯能同时播放多种样式吗？

- **现象/问题**：学生想"红闪 + 蓝闪 同时"。
- **原因**：单颗 WS2812 任一时刻只能显示一种颜色。
- **方案**：把每条样式看作时间函数 `f(t)`，以 20ms 为最小间隔采样合成：亮灭取 OR，颜色通道相加截断（红蓝重叠时显紫）。
- **教学点**：物理限制 → 数学建模 → 近似实现 → 代价评估（CPU/内存可忽略），完整的工程思维链。

### 案例 9：电脑 IP 变了，板子全部离线

- **现象**：换网络/重启路由器后，所有板子连不上。
- **原因**：`common/wifi_config.py` 里的 `SERVER_IP` 是旧地址。
- **修复**：查看新 IP → 更新配置 → 重新 `deploy.py` 部署两块板。
- **教学点**：IP 是动态的；配置与代码分离、密钥不入库的工程意义。

## 七、故障排查速查表

| 现象 | 优先检查 | 处理 |
|---|---|---|
| 找不到 COM 口 | USB 线/驱动/设备管理器 | 换数据线；装 CH343 驱动；`python -m mpremote devs` |
| `could not open port` | 端口被占用 | 关闭 Thonny/串口助手/bridge 后重试 |
| `flash-id` 超时 | 端口错误/板子未进下载模式 | 确认端口；按住 BOOT 再点 RST 后重试 |
| 烧录后无输出 | 未复位 | `python -m mpremote connect COMx reset` |
| 灯不亮但程序在跑 | 引脚/像素数错误 | 确认 GPIO48、`NeoPixel(pin, 1)` |
| `raw repl` 失败 | 偶发时序 | 等 2 秒重试；重插 USB |
| 板子反复 `connect failed` | WiFi 密码/频段/SERVER_IP | 用手机热点验证 2.4G；核对 IP；先跑 mini_server |
| 转发器无连接日志 | 板子没连到 Windows | 确认 `SERVER_IP` 是电脑 WLAN IP、6000 端口未被占用 |
| WSL 里 `ros2` 找不到 | 未 source | `source /opt/ros/jazzy/setup.bash` + `source install/setup.bash` |
| `colcon build` 报缺依赖 | 系统依赖未装 | `rosdep install --from-paths src --ignore-src -y`（或按报错安装） |
| 页面打不开 | WSL localhost 不转发 | 用 `hostname -I` 得到 WSL IP 访问，或 `UI_HOST=0.0.0.0` |
| 页面还是旧版 | 浏览器缓存 | `Ctrl-F5` 强刷 |
| 指令无响应 | 板子离线/指令错 | 看 `wifi_server` 是否打印 `offline, dropping`；核对指令表 |
| 串口乱码 | 波特率 | 固定 115200 |

## 八、分层任务设计建议

| 学生类型 | 基础任务（必须） | 拓展任务（选做） |
|---|---|---|
| 慢热型 | 完成实验验收点，能复述操作步骤 | 给同学讲一遍自己的操作流程 |
| 标准型 | 完成验收点 + 思考题 | 修改一个参数并预测结果、验证 |
| 进阶型 | 全部完成 | 实现实验九 `PING/PONG`、实验十一界面改进、自拟小功能 |

**课堂提速技巧**：把常用命令写成卡片贴在显示器旁（flash-id、deploy、launch、topic pub 各一张）。

## 九、安全与合规检查清单（每次实验课前强调）

- [ ] USB 供电，严禁外接电源与 5V 信号直连 GPIO；
- [ ] 防静电、防短路（板子放在绝缘桌面，不放在金属上）；
- [ ] RGB 练习亮度 ≤100；
- [ ] WiFi 密码不投屏、不截图、不提交到任何仓库；
- [ ] 控制页面默认只绑定本机（`127.0.0.1`），仅在实验需要时由教师设置 `UI_HOST=0.0.0.0`；
- [ ] 路由器独立组网，不接入校园网核心。

## 十、课后延伸与学习路径

1. **传感器扩展**：DHT11/超声波/光敏 → 把物理量映射为颜色或闪烁频率（I2C/ADC 入门）。
2. **ROS 2 深入**：自定义消息类型、服务/动作、`rqt` 可视化、Nav2 入门。
3. **竞赛与项目**：嵌入式设计竞赛、机器人大赛、物联网创新赛；本课程作品可直接作为参赛原型。
4. **推荐练习**：把 `MIX` 的合成规则改为"平均"或"取最大"，对比观感；给 `led_ui` 增加"一键灯效"按钮。
