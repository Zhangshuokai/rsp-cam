# 《ESP32 与 ROS 2 开发基础》教学单元设计（16 周 × 3 学时）

> 使用说明：每周 3 学时建议按 **45 分钟讲解演示 + 90 分钟动手实践** 组织。
> 教师上课前先按"课前 5 分钟检查清单"过一遍（见 [05-教师手册.md](05-教师手册.md)）。
> 标注 ⭐ 的是当堂验收点，学生完成即得分。

---

## 第 1 周｜单元 1：认识开发板与开发环境

**教学目标**
- 认识套件：ESP32-S3 N16R8、USB 串口芯片 CH343、板载 RGB（GPIO48）、BOOT 键（GPIO0）。
- 安装 Python 工具链（`esptool`、`mpremote`）并完成 `flash-id` 探测。
- 理解"开发板出厂固件不是 MicroPython，需要重新烧录"。

**重点**：开发板与电脑的通信通道（USB→CH343→串口）；工具的正确调用方式 `python -m esptool`。
**难点**：识别板子的 COM 口；区分"仅供充电"与"数据"USB 线。

**教学流程**
1. 课程导入（10 min）：展示最终项目（双板 LED + ROS 2 控制台），说明 16 周后每位同学能做什么。
2. 硬件认识与安全规范（15 min）：供电、3.3V 逻辑、防静电、亮度安全。
3. 工具链安装（20 min）：`python -m pip install esptool mpremote`，验证 `python -m esptool version`。
4. 探测板子（30 min）：设备管理器中找 CH343 → 确定 COM 口 → `flash-id` 读取芯片信息。
5. 观察原厂固件（30 min）：用串口监视器（115200）观察 `example: log -> UART`，说明此刻没有 Python REPL。

**实践与验收**
- ⭐ 每人提交一张 `flash-id` 输出截图，能读出芯片型号（ESP32-S3）、Flash 大小（16MB）和 MAC。

**课后作业**
- 记录：我的板子端口号、MAC、原厂日志内容；预习实验一。

## 第 2 周｜单元 1：烧录 MicroPython 与 REPL

**教学目标**
- 完成"擦除 → 写入固件 → 复位 → 进入 REPL"的完整烧录流程。
- 理解厂商固件是**完整合并镜像**（bootloader + 分区表 + 应用），必须烧写到偏移 **0x0**。
- 会用 `mpremote` 访问设备文件系统。

**重点**：`erase-flash` 与 `write-flash -z 0x0 <厂商固件>`；烧录后验证。
**难点**：中文路径引号；`mpremote` 首次连接失败的重试；串口被其他软件占用。

**教学流程**
1. 原理讲解（20 min）：固件是什么、为什么要擦除、镜像内部结构（bootloader@0x0、分区表@0x8000、应用@0x10000）。
2. 教师演示烧录（20 min），强调命令拼写与引号。
3. 学生实操（60 min）：两人一组互检；失败时按"换端口→重试→检查占用"顺序排查。
4. REPL 体验（25 min）：`python -m mpremote connect COMx` 或 Thonny，执行 `print(...)`、`import sys; sys.implementation`。

**实践与验收**
- ⭐ REPL 中打印出 `MicroPython` 版本号；⭐ `python -m mpremote connect COMx fs ls` 能看到设备目录。

**课后作业**
- 用自己的话写出烧录三步曲；思考"如果烧到 0x1000 会怎样"。

## 第 3 周｜单元 2：MicroPython 编程与 LED 控制

**教学目标**
- 掌握变量、`while` 循环、函数、`time.sleep_ms` 的基本用法。
- 理解 RGB 三通道颜色值（0–255）与亮度控制。
- 用 `neopixel.NeoPixel`（GPIO48）编写"绿色 500ms 闪烁"程序。

**重点**：`from machine import Pin` + `NeoPixel` 的固定写法；程序必须命名为 `main.py` 才会开机自启。
**难点**：缩进即语法；"灯灭"是写入 `(0,0,0)`。

**教学流程**
1. 现象导入（10 min）：先展示做好的绿色闪烁，制造"我也要做一个"的兴趣。
2. 像素与颜色（20 min）：三通道混合演示（红绿蓝→白/黄/紫），强调低亮度练习值。
3. 讲解最小程序骨架（25 min）：初始化、循环、写像素、延时。
4. 学生实践（65 min）：编写并上传自己的闪烁程序，修改颜色/周期。
5. 串口标识（15 min）：在闪烁的同时打印 `[GREEN ON]`/`[GREEN OFF]`，为后续调试做铺垫。

**实践与验收**
- ⭐ 板载 RGB 按自选颜色和周期闪烁；⭐ 串口同步输出开/关标识。

**课后作业**
- 计算并验证：`(0,100,0)` 与 `(0,255,0)` 的观感差异；把周期改为 100ms 和 2s 各试一次。

## 第 4 周｜单元 3：工程化组织与一键部署

**教学目标**
- 理解"公共模块 + 专用入口"的分工：`common/board_common.py` 与 `green/main.py`、`blue/main.py`。
- 会使用 `tools/deploy.py` 一键部署（上传公共模块 + WiFi 配置 + 板级入口 + 重启）。
- 初步接触版本管理：`git status / add / commit`（以教师演示为主）。

**重点**：设备端 `board_common.py` 可被 `main.py` 直接 `import`；部署 = 上传文件 + 复位。
**难点**：为什么"链式 cp + reset"会让板子停在 REPL（历史 bug 与修复）。

**教学流程**
1. 对比导入（15 min）：单文件程序 vs 两板共享公共模块的工程结构，讨论哪个好维护。
2. 阅读与讲解 `deploy.py`（25 min）：重试机制、两次独立 mpremote 连接的原因。
3. 学生实操（60 min）：两块板分别部署 green/blue，观察各自颜色与标识。
4. Git 演示（20 min）：教师现场 `git log --oneline` 回顾项目演进，演示查看某个提交改了什么。

**实践与验收**
- ⭐ 绿板/蓝板通过 `python tools\deploy.py COMx green|blue` 部署成功并正常闪烁。

**课后作业**
- 至少能对 `python tools\deploy.py COM13 green` 的每一步给出解释（上传了什么、为什么重试、为什么单独 reset）。

## 第 5 周｜单元 4：串口通信与协议设计

**教学目标**
- 理解串口（UART/USB 转串口）作为调试通道的作用。
- 认识心跳机制：`DATA <NAME> <seq>` 每 4 秒一次，用于"我还活着"的在线判断。
- 理解行协议：一行一条消息，以 `\n` 分隔；收到消息后的 `[RX]` 打印与白灯提示。

**重点**：心跳与超时判断思想；协议字段含义（名字、序号）。
**难点**：为什么"在线状态"要用心跳而不是连接状态来判断。

**教学流程**
1. 串口原理（20 min）：波特率、数据位、为什么笔记本上看到的是 COM 口。
2. 读心跳（25 min）：用串口监视器读 `DATA GREEN 1,2,3...`，观察每 4 秒 +1。
3. 协议设计讨论（30 min）：如果让你设计一条控制指令，需要哪些字段？引出后续 `LED/COLOR/STYLE`。
4. 实践（45 min）：在 REPL 中用 `bc.StyleSet(...).apply("COLOR 255 0 0")` 体验解析器（实验五步骤 5）。串口是只输出的调试通道，不接收指令；`[RX]` 与白闪的观察放到实验六的 WiFi 链路中进行。

**实践与验收**
- ⭐ 能解释 `DATA` 与序号的作用；⭐ 在 REPL 中让解析器执行一条 `COLOR` 指令并打印出状态。

**课后作业**
- 设计 1 条自己的指令（如 `PING`），写出格式与应答；思考如何避免与现有指令冲突。

## 第 6 周｜单元 5：WiFi 联网与 TCP 通信

**教学目标**
- 理解网络三要素：IP 地址、端口、协议；理解 TCP 客户端—服务器模型。
- 阅读并配置 `common/wifi_config.py`（SSID / 密码 / SERVER_IP / SERVER_PORT）。
- 观察板端连接日志：`link up <IP>:<PORT>` 与断线重连（每 4 秒重试）。

**重点**：`HELLO <NAME>` 注册；心跳走 WiFi 后串口只做调试输出。
**难点**：连不上服务器时如何判断是"板子没联网"还是"服务器没启动"。

**教学流程**
1. 网络模型（25 min）：用"打电话"类比 IP/端口；对比串口与网络的差别（一对一 vs 多设备）。
2. 配置讲解（20 min）：**强调 `wifi_config.py` 含密码，不入库、不投屏、不截图**。
3. 学生配置与部署（45 min）：填入本组热点的 SSID/密码和教师给定的 `SERVER_IP`，重新部署。
4. 验证（30 min）：串口日志出现 `link up`；若失败，记录错误码作为下节课素材。

**实践与验收**
- ⭐ 板子串口打印 `link up`（或明确打印出失败原因，并完成一次重试观察）。

**课后作业**
- 画一张数据路径图：板子 → 热点 → 电脑 → WSL，标出 IP 与端口。

---

## 第 7 周｜单元 5：网络链路排障与转发器

**教学目标**
- 复现并解释"板子能连电脑、但连不上 WSL"的真实故障。
- 使用 `tools/tcp_forwarder.py` 打通 LAN → WSL 链路，理解其必要性（WSL 镜像网络下的入站限制/防火墙）。
- 掌握分层排障法：物理层 → 网络层 → 端口 → 应用层。

**重点**：`forwarder` 监听 `0.0.0.0:6000`，转发到 WSL 的 `127.0.0.1:6001`。
**难点**：分清两台"电脑"（Windows 与 WSL）各自的 IP 与端口。

**教学流程**
1. 故障复现（20 min）：板子连 Windows 监听端口成功、连 WSL 端口失败，现场用两段最小测试代码对比。
2. 原因分析（20 min）：WSL 网络模式与 Hyper-V 防火墙；引出"不做管理员改防火墙，改用转发器"的工程折中。
3. 启动链路（25 min）：Windows 端 `python tools\tcp_forwarder.py ...`；WSL 端 `ros2 launch board_bridge wifi.launch.py`。
4. 全链路验证（40 min）：两块板部署 WiFi 版固件 → `wifi_server` 日志出现 `green registered` / `blue registered`。

**实践与验收**
- ⭐ `wifi_server` 日志出现两块板注册；⭐ 板间 `FROM` 转发（relay 工作正常）。

**课后作业**
- 按"现象—假设—验证—结论"格式写一份排障记录（不少于 4 条假设）。

## 第 8 周｜单元 6：ROS 2 核心概念与命令行

**教学目标**
- 说出节点（Node）、话题（Topic）、消息（Message）的含义及发布/订阅模型。
- 会用 `ros2 node list`、`ros2 topic list/echo/pub` 观察系统。
- 理解"话题是广播，不是点对点"。

**重点**：`std_msgs/String` 类型；话题命名 `/board/green/tx`。
**难点**：分布式概念抽象——建议类比"微信群"：节点=群成员，话题=群，消息=群消息。

**教学流程**
1. 概念类比（25 min）：节点/话题/消息/服务/参数，重点只讲话题。
2. 小例子（30 min）：运行系统自带示例（如 `demo_nodes_cpp talker/listener`）或两个终端 pub/echo 同一话题。
3. 打开项目（30 min）：观察 `ros2 topic list` 中 `/board/green/rx`、`/board/green/tx` 等。
4. 实践（35 min）：学生自己 `ros2 topic pub --once` 向项目话题发一条消息并观察 echo。

**实践与验收**
- ⭐ 两人一组：一人发布、一人 echo，截图证明消息收到；⭐ 能说出 `tx` 与 `rx` 的方向。

**课后作业**
- 用 `ros2 topic info` 查看消息类型，写入实验记录。

## 第 9 周｜单元 6：工作空间、功能包与 launch

**教学目标**
- 理解 ROS 2 工作空间目录：`src/`（源码）、`build/`（中间产物）、`install/`（安装结果）。
- 会 `colcon build` 构建 `board_bridge` 包并 `source install/setup.bash`。
- 会读 `launch` 文件，了解一次启动多个节点的方法与环境变量参数。

**重点**：`setup.py` 中入口点（executable）与 launch 安装目录；`WIFI_PORT`/`UI_PORT`/`UI_HOST` 环境变量。
**难点**：修改代码后必须重新 build 才生效；source 的层级（系统 ROS → 工作空间）。

**教学流程**
1. 目录结构（20 min）：对照 `ros2_ws/` 实际目录讲解。
2. 构建演示（25 min）：`colcon build`，解读输出与常见报错。
3. 读 launch（25 min）：`wifi.launch.py` 同时启动 `wifi_server`、`relay`、`led_ui` 三个节点。
4. 学生实践（50 min）：修改 launch 中节点名/参数后重新构建并启动，验证生效。

**实践与验收**
- ⭐ `colcon build` 成功；⭐ 修改 `UI_PORT` 环境变量后页面端口变化。

**课后作业**
- 解释 `source install/setup.bash` 的作用；记录不 source 时 `ros2 run board_bridge ...` 的报错。

## 第 10 周｜单元 7：桥接节点解析（TCP ↔ 话题）

**教学目标**
- 读懂 `wifi_server.py` 主流程：监听端口 → 等待 `HELLO` 注册 → 每行数据发布到 `/board/<board>/rx`。
- 理解订阅 `/board/<board>/tx` 后把消息写回板子（`sendall` + `\n`）。
- 知道为什么用锁（多线程同时读写连接表）。

**重点**：一行 TCP 数据 = 一条话题消息；话题名由板名拼出。
**难点**：回调函数、消息对象 `msg.data`。

**教学流程**
1. 代码走读（35 min）：按"初始化 → 接受连接 → 注册 → 收/发"四段讲。
2. 模拟客户端实验（30 min）：用一个 Python 小客户端连接 `6001`，发送 `HELLO green` 和若干行，观察 `ros2 topic echo /board/green/rx`。
3. 订阅实验（25 min）：`ros2 topic pub` 到 `/board/green/tx`，观察客户端收到数据。
4. 讨论（10 min）：如果两个板子同名注册会怎样？断开后重连呢？

**实践与验收**
- ⭐ 用模拟客户端让 `rx` 话题出现自己发的消息；⭐ 向 `tx` 发消息后客户端能收到。

**课后作业**
- 画出 `wifi_server` 的时序图（板子、服务器、ROS 话题三者之间）。

## 第 11 周｜单元 7：LED 指令控制与板间转发

**教学目标**
- 通过 `/board/<board>/tx` 发送 `LED/COLOR/PERIOD/PATTERN/RESET` 指令控制真实板子。
- 理解 `relay` 节点：把收到的 `DATA <SRC> <seq>` 改写为 `FROM <SRC> <seq>` 发给另一块板。
- 能串联完整链路：命令行 → 话题 → TCP → 板子 → 执行 → 回传。

**重点**：`ros2 topic pub --once` 的引号与消息格式；指令执行后的板端回复。
**难点**：链路上任何一环失败时的定位顺序。

**教学流程**
1. 指令速查（15 min）：回顾指令表（见附录）。
2. 全链路演示（20 min）：改绿板颜色，串口观察 `[RX GREEN]` 与颜色变化。
3. 学生实操（50 min）：每人至少完成 3 条指令（含 RESET）并改变真实灯效。
4. relay 解析（25 min）：讲解 `FROM` 消息，观察另一板的 `[RX]`。

**实践与验收**
- ⭐ 用 ROS 2 命令成功改变板子颜色/周期；⭐ 在两块板的串口都看到 `FROM` 转发。

**课后作业**
- 写一条新指令的端到端测试记录（发什么、板子回什么、灯怎么变）。

## 第 12 周｜单元 8：板端样式管理与解析器

**教学目标**
- 掌握 `STYLE SET/DEL/USE/LIST` 的语义：**保存与应用分离**。
- 理解 `default` 样式的"不可删除、不可覆盖"设计及其意义（原始闪烁永不丢失）。
- 读懂 `StyleSet.apply()` 的分发结构，能定位一条指令的处理分支。

**重点**：`STYLE SET` 只保存，`STYLE USE` 才切换；`STYLE LIST` 的回包格式。
**难点**：为什么要把"保存"和"应用"分开（历史上真实踩过的坑：保存时误切换）。

**教学流程**
1. 设计讨论（20 min）：目标 = 多样式并存 + 原有闪烁不消失；如何设计命令与数据结构？
2. 命令实验（45 min）：创建 3 条样式、逐个应用、删除、尝试删 `default` 观察 `STYLE-ERR protected`。
3. 代码走读（40 min）：`apply` → `_style` 分支；错误回复的种类。
4. 小结（15 min）：状态如何保持一致（active/playlist/mixlist 的相互关系）。

**实践与验收**
- ⭐ 完成"增—用—删"全套操作，`default` 始终存在；⭐ 解释 `STYLE-ERR protected` 的含义。

**课后作业**
- 用流程图画出 `STYLE SET/USE/DEL/LIST` 对 `styles`、`active` 两个状态的影响。

## 第 13 周｜单元 9：轮播与并行混合（时间合成）

**教学目标**
- 理解 `PLAY <name...>` 顺序轮播：每个样式播放 4 个周期后切换。
- 理解 `MIX <name...>` 并行混合：以 20ms 为最小间隔采样各样式瞬时状态，亮灭取 OR、颜色通道相加截断。
- 能解释"单灯无法真正同时显示多色，但可用时间复用近似"。

**重点**：把样式看作时间的函数 `f(t)`；合成规则。
**难点**：相位、周期差异导致的拍频；采样间隔与 CPU 开销的权衡。

**教学流程**
1. 问题讨论（20 min）：一颗灯能同时播放红闪与蓝闪吗？→ 物理限制 → 时间复用方案。
2. 数学建模（25 min）：`lit = (t // period) % 2 == 0`；举 2×2 时序表例子。
3. 实验对比（45 min）：先 `PLAY a b c` 看顺序切换，再 `MIX a b c` 看合成效果（红+蓝重叠时段变紫）。
4. 代价分析（15 min）：20ms tick 的刷新频率、CPU 占用与内存占用结论（可忽略）。

**实践与验收**
- ⭐ 轮播至少 3 条样式且不删除任何样式；⭐ 混合红(快闪)+蓝(solid) 并描述观察到的规律。

**课后作业**
- 列表计算：红 100ms 闪烁 + 蓝 300ms 闪烁在 0–600ms 的合成颜色变化。

## 第 14 周｜单元 10：Web 控制台与人机交互

**教学目标**
- 理解 `led_ui` 的结构：HTTP 服务 + 内嵌页面 + ROS 2 发布/订阅。
- 通过页面完成样式管理、轮播、混合与在线状态查看。
- 了解两个安全/体验设计：只绑定本机地址（`127.0.0.1`，可用 `UI_HOST` 覆盖）、响应禁用缓存（`no-store`）。

**重点**：浏览器 → `/api/send` → `/board/<board>/tx` → 板子；板端回传 → `/board/<board>/rx` → 页面日志。
**难点**：为什么页面要显示"在线/离线"；旧页面缓存导致"每次刷新多出样式"的复盘。

**教学流程**
1. 启动与访问（20 min）：启动 launch，浏览器打开（WSL IP:8080 或 `UI_HOST=0.0.0.0`；后者会把无鉴权页面暴露到局域网，仅在隔离实验局域网、经教师确认后使用）。
2. 功能演练（45 min）：保存样式（不改变当前闪烁）→ 应用 → 轮播所选 → 混合所选 → 恢复默认。
3. 代码浏览（30 min）：HTTP 路由、页面轮询、在线判定（心跳超时 10 秒）。
4. 复盘讨论（15 min）：如果保存样式会立刻切换闪烁，用户会有什么感受？（需求来自真实用户反馈）

**实践与验收**
- ⭐ 页面上完成一次"保存不覆盖 + 应用切换 + 轮播 + 混合 + 恢复默认"全过程。
- ⭐ 拔掉/重启一块板，观察页面在线状态变化。

**课后作业**
- 提出并实现（选做）一个界面小改进，如显示最近一条 RX 时间或新增快捷颜色按钮。

## 附录：板端指令速查（第 8 周起使用）

```
HELLO <NAME>                 # 板子连接服务器时的注册（固件自动发送）
DATA <NAME> <seq>            # 心跳，每 4 秒（固件自动发送）
STYLE SET <name> <R> <G> <B> <PERIOD_MS> [solid|blink]   # 保存（不切换）
STYLE DEL <name>             # 删除（default 受保护）
STYLE USE <name>             # 激活
STYLE LIST                   # 查询，回 STYLE ... 多行 + PLAYING/MIXING + STYLE-END
PLAY <name> [<name> ...]     # 顺序轮播（每样式 4 个周期）
PLAY STOP                    # 停止轮播
MIX <name> [<name> ...]      # 并行混合（20ms 最小间隔采样）
MIX STOP                     # 停止混合
LED <R> <G> <B> <PERIOD_MS>  # 改当前样式：颜色+周期
COLOR <R> <G> <B>            # 只改颜色
PERIOD <MS>                  # 只改周期（别名 BLINK）
PATTERN solid|blink          # 常亮 / 闪烁
RESET                        # 恢复本板默认闪烁（不删除自定义样式）
```

ROS 2 侧对应话题：

- 发往板子：`/board/green/tx`、`/board/blue/tx`（`std_msgs/String`）
- 板子回报：`/board/green/rx`、`/board/blue/rx`（含 `STYLE ...`、`DATA ...`、`FROM ...`）
